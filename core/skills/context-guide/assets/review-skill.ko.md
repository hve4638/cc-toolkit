{{file}} 수정됨. 변경분을 아래 기준으로 점검하고, 위반은 지금 고친다.

1. remove-test — 추가한 줄을 지웠을 때 이 스킬을 실행하는 모델의 행동이 달라지는가? 안 달라지면 사족이니 뺀다. 스킬 자체에 대한 메타 설명(대상 독자, 범위 선언, 중요성 강조), bullet 뒤에 붙인 근거 꼬리가 주로 걸린다.
2. 같은 폴더에 SKILL.md / SKILL.ko.md 페어가 있으면 이번 세션에서 다른 쪽도 같이 갱신한다. 섹션 구조, bullet 수, 코드펜스 안 식별자·메시지, frontmatter 기능 필드가 일치해야 한다.
3. description 은 what + when 만 담는다(3인칭). 행동 규칙이 description 에 들어갔으면 본문으로 옮긴다.
4. 본문 산문에서 $ARGUMENTS 를 변수처럼 참조하지 않는다 — 호출 시 실제 입력으로 치환되어 사라지는 토큰이다. 사용자 입력은 자연어로 지칭한다. 말미의 `Task: $ARGUMENTS` 컨벤션은 예외.
5. 산문은 평이한 표준어로 쓴다. 구어체 동사, 과한 bold, 개념당 여러 용어 혼용을 피한다. 사용자가 대화에서 쓴 표현이라도 표준어가 아니면("여기다 박는다" 류) 지시문에 옮기지 않는다.

점검 결과를 항목별로 보고한다: `1 문제없음, 2 고침(내용), 3 문제없음, …` 식.
