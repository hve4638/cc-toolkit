# handoff

현재 세션에서 수행·논의한 작업 맥락을 작업 단위로 분할해 단일 파일 `.agent-memory/HANDOFF.md` 의 섹션들로 저장한다. 맥락 0 의 다음 세션 Claude 가 즉시 이어갈 수 있는 형태로 작성한다 (사람용 요약 X).

---

## 저장 규격

- 경로: `.agent-memory/HANDOFF.md` — 고정 단일 파일
- 파일이 이미 존재하면 그 제목 줄을 사용자에게 보여주고 덮어쓸지 물어본 뒤 기록한다.
- 제목 줄: `# Handoff — <title> (<timestamp>)`. 제목은 세션의 지배 주제를 나타내며, 이질적 작업의 혼합이면 `mixed`
- 타임스탬프 조회: `date +"%Y-%m-%dT%H%M"` 등으로 현재 시각 조회

---

## 대화 프로토콜

한 번 호출로 즉시 저장 ✗. **1~2 단계만 사용자와 조율**하고, 그룹핑이 확정되면 **3~5 단계는 자동 진행**한다.
1~2 단계 중에는 "이건 빼라", "이 작업은 더 자세히" 같은 지시가 반복될 수 있으며 그때마다 즉시 반영.

### 1. 전수 나열 (사용자 협의)
현재 세션에서 수행·논의한 **모든 작업 맥락을 빠짐없이** 먼저 사용자에게 나열. 누락 방지가 목표.

### 2. 그룹핑 제안 (사용자 협의)
응집도 기준으로 묶음 안을 제시. 합치기·나누기·제외·추가를 사용자 지시에 따라 반복 조정.

**그룹핑이 사용자 확정되면 3~5 단계는 추가 확인 없이 자동 실행한다.**

### 3. 제목 자동 결정
저장 규격의 제목 줄 규칙에 따라 제목을 자동 선정. 사용자 승인 단계 없음.

### 4. 문서 자동 작성
인덱스 헤더와 작업 섹션들을 자동 작성. 권장 하위 섹션 중 비어 있는 것은 자동 생략.

### 5. 자동 저장
`.agent-memory/HANDOFF.md` 에 즉시 기록 (위 덮어쓰기 확인 이후). 별도 최종 승인 단계 없음.

---

## 문서 구조

파일 하나, 두 부분: 상단의 인덱스 헤더 + 작업당 `##` 섹션 1 개.

### 인덱스 헤더

항상 존재. 다음 세션 Claude 의 진입점.

- 작업 목록 (섹션명 + 한 줄 요약). 각 항목에 `[done]` / `[active]` 상태 마커를 붙인다. `[active]` 는 정확히 1 개 (또는 0 개 — 세션이 자연스럽게 종결된 경우).
- 우선순위 / 의존관계
- "어디부터 읽을지" 명시적 안내
- 현재 컨텍스트 — `[active]` 로 표시된 섹션 1 개를 명시. **pickup 의 "다음 할 일" 응답이 참조하는 유일한 출처**. 활성 작업이 없으면 `없음 (세션 종결)` 로 명시.

### 작업 섹션

- 고정 내부 구조 없음 → 작업 응집도 기반 동적 분할
- 응집력 있는 작업 묶음 = 1 섹션. 완전히 독립인 작업 = 별도 섹션.
- 크기가 적절한지의 기준은 "다음 세션 Claude 가 섹션 하나 단위로 이해 가능한가"

작업당 권장 하위 섹션 (느슨, 비면 생략):
- 의도 — 사용자가 원래 하려던 것과 왜
- 지금까지 — 진행 연대기
- 결정과 이유 — 선택지 / 고른 것 / 이유 (롤백 방지)
- 미해결 — 미정 / 블로커 / 답변 대기
- 다음 수 — 즉시 실행 가능한 액션. **세션 마지막에 진행 중이던 작업 1 건에만 기록**한다.

### 작성 규칙
- 참조는 **파일 경로 + 라인 번호 + 의도**만 — 코드 블록 복붙 없이
- "무엇을 했다" 가 아니라 "왜 했다 / 어디까지 왔다 / 다음 수"

## 세션 맥락만 정리 (soft)

handoff 는 현재 세션에서 이미 아는 맥락만 정리한다.

예외 (파일시스템 탐색 허용):
- 모호·모순 영역의 사실 확인
- 사용자가 명시적으로 탐색을 지시한 경우

---

## memory 승격

handoff 에 담은 내용 중 프로젝트 영구 지식이 될 사항은 별도로 memory (MEMORY.md) 에 승격한다. handoff 자체는 세션 일회성이다.
