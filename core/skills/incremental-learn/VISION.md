# VISION — incremental-learn

이 문서는 스킬이 시작될 때의 의도를 기록한 것이다. 구현이 진행되어도 갱신하지 않고 얼려 둔다. 이후 제안이 이 방향에서 벗어나거나 스킬의 목적을 넘어 커질 때, 그 제안을 이 문서에 대어 보는 기준으로 쓴다.

## 무엇인가

core 플러그인의 단일 스킬. 실작업 중 사용자가 모르는 개념을 만나 직접 호출하면, 그 개념만 떼어낸 일회용 샌드박스(빈 repo나 최소 구성)를 만들어 학습 구간을 연다. 아는 부분은 에이전트가 빠르게 처리하고, 모르는 부분만 사용자가 직접 손으로 수행한다. 이해가 되면 샌드박스를 버리고 실작업으로 복귀한다.

## 왜

에이전트의 작업 속도는 사용자의 이해 속도를 앞지른다. 산출물은 쌓이는데 사용자의 지식은 그대로면, 사용자는 자기 프로젝트의 작업물을 따라가지 못하게 된다. 이 스킬은 산출물이 아니라 지식을 목적으로 한다. 사용자가 무엇을 알고 무엇을 모르는지 경계를 확인하고, 모르는 것을 가장 작은 형태로 직접 만져 보게 해서, 적당한 개입과 적당한 템포의 지식 습득 텀을 확보한다.

## 비목표

- 튜토리얼이나 학습노트 문서를 생성하지 않는다. 학습은 글을 읽는 것이 아니라 샌드박스에서 손으로 따라가는 것으로만 이루어진다.
- 실작업과 무관한 일반 학습을 다루지 않는다. 커리큘럼식 교육이 아니며, 항상 지금 하던 작업에서 막힌 개념만 다룬다.
- 퀴즈나 이해도 평가를 하지 않는다. 이해했는지는 사용자가 스스로 판단한다.
- 샌드박스를 보존하거나 재사용하지 않는다. 학습 구간이 끝나면 버려도 되는 일회용이다.
- 세션을 넘어 지식 상태를 추적하지 않는다. 호출은 단발이고, 지식 대장 같은 기록을 남기지 않는다.

## 전제

- 모르는 것의 식별은 사용자 몫이다. 사용자가 모른다고 느낄 때 스킬을 호출하며, 에이전트가 사용자의 무지를 먼저 탐지하지 않는다.
- 학습 대상 개념은 실프로젝트의 복잡도에서 떼어내, 샌드박스에서 가장 작게 확인 가능한 형태로 재현한다.
- 설명보다 실행이 먼저다. 사용자가 직접 실행하고 결과를 눈으로 확인하는 것이 학습의 단위다.

## 시나리오

- github-action을 만들어야 하는데 action을 해본 적이 없다. 샌드박스 repo를 만들어 최소 workflow를 사용자가 직접 작성하고 트리거해 본 뒤, 이해한 상태로 실작업의 action 구성으로 복귀한다.
- 자기 서버에 배포를 연결해야 한다. 샌드박스에 연결만 간단히 확인할 수 있는 구성을 만들고, 연결 단계를 사용자가 직접 수행해 동작을 확인한 뒤 실작업으로 돌아간다.
