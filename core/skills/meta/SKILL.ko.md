# meta

주어진 인자를 완성된 프롬프트로 바꾼다. 결과는 채팅에만 출력하고 파일은 쓰지 않는다.

## Mode

인자로부터 모드를 판정한다:
- 다듬을 기존 프롬프트면 improve 모드.
- 작업·목표 설명이면 generate 모드.

어느 쪽인지 불분명하면 진행 전에 가정을 밝힌다.

## Clarify first

무엇이든 산출하기 전에 핵심이 갖춰졌는지 확인한다: 작업·목표, 대상 청중 또는 모델, 요구 출력 형식, 하드 제약.

핵심이 빠졌거나 모호하면 표적 질문 1~2개를 던진 뒤 산출한다. 답 없이 산출할 때는 세운 가정을 각각 밝힌다.

## Generate

벤더 중립 프롬프트를 만든다. 제 몫을 하는 부분만 넣는다:

1. 역할 줄. 전문가 페르소나가 작업을 또렷하게 할 때.
2. 맥락과 입력. 변수는 `[대괄호 플레이스홀더]`로.
3. 작업 지시. 구체적이고 모호하지 않은 표현, 맹탕 문구 없이.
4. 추론을 결과보다 먼저: 추론 단계 먼저, 결론 마지막. 예시가 결론을 먼저 보이면 순서를 뒤집는다.
5. 출력 형식을 명시: 구조, 길이, 문법.
6. 예시. 선택. 같은 플레이스홀더 재사용.

XML 태그나 handlebars 변수 같은 벤더 전용 장치는 사용자가 요청하지 않으면 피한다.

## Improve

원래 의도와, 인자가 이미 담은 방대한 가이드라인·예시를 보존한다. 프롬프트가 이미 단순하면 변경을 최소화하고, 복잡하면 구조를 다시 쓰지 않은 채 명확성을 벼리고 빈틈을 메운다. generate 골격과 추론 순서는 프롬프트를 강하게 하는 선에서 적용한다.

## Output

- 완성된 프롬프트를 복사 가능한 펜스 블록 하나로.
- 사용한 모드와 남은 질문을 적은 짧은 노트.
- improve 모드면 무엇을 왜 바꿨는지 간단한 목록.
