# skillify-stepform

스텝 하나가 폼 하나인 스킬을 짓는 규칙. 절차는 SKILL 산문이 아니라 스크립트가 들고, 에이전트는 폼을 채워 제출한다.

절차가 결정적일 때 이 설계를 쓴다 — 파일을 만들고 옮기고, 설정을 쓰고, 검증 가능한 상태 전이를 밟는 일. 산출물이 글이고 판단이 본체면 산문으로 남긴다.

## 폼과 제출

스텝은 `--answer` 로 완전한 답을 받았을 때만 움직인다. 무인자 호출도, 키가 빠진 호출도 아무것도 바꾸지 않고 지금 상태와 다음 할 일만 낸다.

답이 갖춰지기 전까지 같은 스텝을 몇 번을 불러도 순수 조회이므로, 절반만 반영된 상태는 생길 자리가 없다.

빠진 키가 있으면 무엇이 비었는지를 `<error>` 로 내고, 그 키를 채울 `<question>` 을 함께 낸다.

## 한 스텝 = 한 동작

완전한 제출은 딱 한 동작을 수행하고 다음 폼을 건넨다. 동작을 마치면 무엇을 지웠고 옮겼고 만들었는지를 `<info>` 로 밝힌다.

## 역할 경계

파일의 생성·이동·삭제·복사는 스크립트가 한다. 에이전트는 읽고, 묻고, 내용을 편집한다.

## 출력이 지침

각 출력은 지금 상태, 사용자에게 물을 것, 다음에 실행할 정확한 명령을 담는다.

SKILL 본문에는 첫 스크립트를 실행하라는 지시와 태그의 의미만 둔다. 스텝이 몇 개인지도 인자 문법이 무엇인지도 런타임에 출력이 알려준다.

## 태그

출력의 최상위 절은 태그로 감싸고, 태그 안은 마크다운으로 쓴다.

- `<status>` — 지금의 사실
- `<question>` — 사용자에게 물을 것
- `<alert>` — 사용자에게 전달할 경고
- `<error>` — 스크립트의 기계 판정
- `<info>` — 수행 내역
- `<next>` — 다음에 실행할 명령

## 질문

선택지는 그것이 만들 JSON 값과 함께 낸다.

선택지가 하나뿐인 자리는 채울 값을 찍는다.

게이트 실패는 한 번에 모아 낸다.

## 메시지 파일

출력 산문은 `messages/` 의 md 파일에 두고, 스크립트는 변형마다 파일을 고른다. 분기는 스크립트가 지고 산문은 md 가 진다.

`{KEY}` 치환은 양방향으로 엄격하다. md 에 값이 안 온 플레이스홀더가 남아도, 넘긴 값이 md 에 안 쓰여도 실패다. 실패는 `file:line` 힌트와 함께 사용자에게 내부 에러를 보고하라는 지시를 내고 0 이 아닌 코드로 끝낸다.

## 확장 지점

선택지는 폴더 하나가 하나다. 스크립트는 목록과 요약 한 줄만 읽고 내용은 모르며, 폴더를 더하면 선택지가 는다.

선택지마다 갈리는 옵션은 answer 의 키로 받는다.
