<worktree_instruction>
이 폴더의 워크트리들은 전역 `wtree` 명령(정책 기반 워크트리 도구)이 관리한다. 브랜치·워크트리의 생성·병합·정리는 wtree 동사로 한다 — `git worktree remove`·`git branch -D`·브랜치 rename 을 직접 하면 이 워크트리는 관리 밖으로 떨어져 wtree 가 동사를 거부하기 시작한다.

- 길을 잃으면 인자 없이 `wtree` — 지금 이 워크트리에서 통과하는 동사만 나온다. `wtree info` 는 정체성·부모·적용 규칙·동사별 미리보기를 보여준다.
- wtree 가 거부하면 사유와 해법이 같이 출력된다. 안내를 따르거나 사용자에게 보고한다.

**작업을 부모에 올릴 때** (사용자가 "merge 해"): `wtree merge [-m "<메시지>"]`. 기록된 부모로만 올라가고, 워크트리는 남는다.

- 방식(squash/rebase/no-ff/ff)은 부모의 정책이 정한다. 허용이 하나면 플래그 생략, 여럿이면 `--squash` 등으로 지정한다. squash·no-ff 는 `-m` 필수, rebase·ff 는 `-m` 거부.
- 커밋된 것만 올라간다. 미커밋 변경은 merge 동안 stash 로 치워졌다가 그대로 돌아온다.
- 정책이 squash 면 어차피 커밋이 하나로 합쳐지니 작업 중엔 자유롭게 커밋한다. 버전 bump 처럼 한 번만 반영돼야 하는 변경은 마지막 merge 직전에 한 번만 한다.
- 충돌을 예고하며 멈추면 아무것도 바뀌지 않은 상태다. 안내대로 이 워크트리에서 해결·커밋한 뒤 재실행한다.

**부모를 당겨올 때**: `wtree sync`. 부모의 진행을 이 브랜치로 merge 한다.

**올리고 작업장까지 끝낼 때** (사용자가 "land 해"): `wtree land [-m "<메시지>"]`. merge 에 이어 destroy 까지 한다. 미커밋 변경이 있으면 시작 전에 거부한다 — 둘 다 하거나 아무것도 안 한다.

**작업장을 정리할 때** (사용자가 "정리해" / "버려"): `wtree destroy`. 워크트리와 브랜치를 없앤다. 잃을 게 있으면(미커밋 변경, 부모 미반영 커밋) confirmation key 를 요구한다 — 사용자에게 확인받은 뒤에만 키를 붙여 재실행한다. 브랜치는 남기고 워크트리만 떼려면 `wtree close`.
</worktree_instruction>
