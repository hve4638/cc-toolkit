# init-ws

대상 폴더를 워크스페이스로 만든다. 워크스페이스는 프로젝트 repo 를 담는 폴더이면서 그 자체는 문서·기록 전용 git repo 다: TODO·계획·버그리포트·결정 기록이 프로젝트 repo 대신 여기에 쌓이고, 내부 프로젝트 repo 는 `.gitignore` 로 추적에서 제외된다.

## 절차

### 1. 대상 확정

사용자가 인자로 폴더를 지정했으면 그 폴더, 없으면 현재 폴더가 대상이다.

`git -C <대상> rev-parse --show-toplevel` 로 repo 상태를 판정한다:

- 대상 자체가 repo 루트 → `git init` 없이 빠진 구성만 채운다.
- 대상이 상위 repo 의 내부 → 중단하고 보고한다. 워크스페이스는 독립 repo 여야 하며, 여기서 만들면 중첩 repo 가 된다.
- repo 아님 → 4단계에서 `git init` 한다.

완료 기준: 대상 경로와 세 갈래 중 어느 경우인지 확정.

### 2. 현황 파악

대상 폴더 바로 아래에서 수집한다:

- `.git` 을 가진 디렉터리와 `*.worktrees` 디렉터리 → 무시 목록
- `CLAUDE.md` / `.gitignore` / `_docs/` 존재 여부

내부 프로젝트 repo 를 하나도 찾지 못하면 대상이 워크스페이스가 맞는지 (프로젝트 repo 자체는 아닌지) 사용자에게 확인하고 답을 기다린다.

완료 기준: 무시 목록과 기존 구성 목록 확보.

### 3. 구성 채우기

빠진 것만 만들고, 이미 있는 파일은 보존한다:

- `.gitignore` — 무시 목록의 디렉터리마다 `<이름>/` 한 줄, 더해서 `.omc/` 와 `.agent-memory/`. 내부 repo 들이 공통 접두어를 공유하면 `<접두어>*/` 글롭 하나로 축약해도 된다. 파일이 이미 있으면 빠진 항목만 덧붙인다.
- `CLAUDE.md` — 없으면 아래 템플릿으로 생성한다. 있으면 워크스페이스 선언이 담겼는지 확인하고, 없으면 템플릿 본문을 기존 내용 앞에 추가한다.

  ```markdown
  # <폴더명>

  <프로젝트> 의 개발 기록·문서를 위한 워크스페이스다. 이 폴더가 곧 문서 repo 이고, 내부 프로젝트 repo (<이름들>) 는 git 추적에서 제외된다.

  TODO·계획·버그리포트·결정 기록은 프로젝트 repo 가 아닌 여기에 저장한다. 별다른 명시 없이 문서를 참조하라고 하면 `_docs/` 를 먼저 확인한다.

  wt 로 워크트리 작업을 부모 브랜치에 merge 했으면 (land 포함), 올라간 커밋마다 `_docs/commits/<단축 해시>.md` 에 그 작업의 의도와 맥락(왜 그런 결정을 내렸는지)을 작성한다. 해시는 wt 가 merge 결과로 출력하는 단축 해시다.
  ```

- `_docs/commits/` 디렉터리

완료 기준: 세 구성요소가 모두 존재.

### 4. git init + 초기 커밋

repo 가 아니었으면 `git init` 한다. 이번에 만들거나 수정한 파일만 명시적으로 `git add <경로>` 하고 커밋한다 (신규 repo 면 `init workspace`, 기존 repo 면 그 로그의 컨벤션을 따른다). 만든 것이 없으면 커밋도 없다.

완료 기준: 이번 생성분이 워킹트리에 미커밋 상태로 남아 있지 않음.

### 5. 보고

- 만든 것 / 이미 있어 보존한 것
- 무시 목록에 넣은 내부 repo
- 폴더명이 `-ws` 로 끝나지 않으면 관례(`<이름>-ws`)와 다르다는 사실
